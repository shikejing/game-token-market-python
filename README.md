# Game Token Market

游戏内代币交易市场后端：支持限价买入/卖出委托、价格优先与时间优先撮合、部分成交、
账户代币托管与结算、提交幂等、重启恢复、行情与账户查询。数据用进程内存承载，
配合本地持久化（WAL + 快照），不依赖任何外部服务。

## 启动

```bash
uv run python main.py
# 或指定数据目录
MARKET_DATA_DIR=/path/to/data uv run python main.py
```

服务默认监听 `127.0.0.1:0`（随机端口），启动后访问 `GET /` 返回 `{"Hello": "World"}`，
`GET /healthz` 返回健康状态。API 前缀为 `/api`。

## 撮合语义

- **委托类型**：限价买入（buy）与限价卖出（sell）。
- **价格优先**：
  - 买单匹配卖单时，从最低卖价开始向上扫描，卖价 ≤ 买价才成交。
  - 卖单匹配买单时，从最高买价开始向下扫描，买价 ≥ 卖价才成交。
- **时间优先**：同一价格档位内，按委托到达顺序（事件序号）排队，先到先得。
- **成交价**：以挂单方（maker）价格成交，吃单方（taker）享受价格改善。
- **部分成交**：未成交部分继续留在挂单簿；完全成交后从挂单簿移除。
- **不成交**：若对手盘价格不交叉，委托以挂单（open/partially_filled）状态留在簿中。

## 托管规则

所有金额与数量均为整数（最小单位），避免浮点误差。

- **提交委托时冻结**：
  - 买入：冻结 `价格 × 数量` 代币（balance → frozen）。
  - 卖出：冻结 `数量` 代币（待售代币）。
- **成交时按成交价与成交量结算**（设成交价为 `p`、成交量为 `q`）：
  - 买方：`frozen -= p×q`，`balance += q`（收到 `q` 代币）。
  - 卖方：`frozen -= q`，`balance += p×q`（收到 `p×q` 代币）。
- **委托结束时释放剩余冻结**：
  - 完全成交或撤单时，将未使用的冻结金额退回账户余额。
  - 买单剩余 = `价格×数量 − Σ(p×q)`；卖单剩余 = `数量 − Σq`。
- **账目守恒**：任意时刻所有账户的 `balance + frozen` 之和等于累计发行代币总量，
  不会出现负余额、重复扣减或超卖。引擎提供 `check_invariant()` 校验不变量。

## 并发与幂等

- **全局串行化**：引擎用一把可重入锁保护所有状态变更。任何并发提交、撤销、撮合
  都等价于某种合法串行执行（可线性化），不会出现负余额或重复结算。
- **提交幂等**：客户端可通过请求体 `client_key` 或 HTTP 头 `Idempotency-Key`
  传入唯一请求标识。同一个 `client_key` 重复到达时：
  - 不会产生多份挂单或重复冻结；
  - 返回结果与首次一致（幂等缓存）。
  - 幂等缓存随持久化保存，重启后仍然有效。
- **撤销幂等**：已完全成交的委托再撤销返回当前状态（no-op），不报错。

## 持久化约定

数据目录（默认 `./data`，可用 `MARKET_DATA_DIR` 覆盖）包含两个文件：

- `journal.log`：追加式事件日志（WAL）。每次状态变更（开户、充值、提交、撤单）
  在内存变更后追加一行 JSON，fsync 落盘。追加失败则回滚内存变更，客户端可安全重试。
- `snapshot.json`：全量快照。原子写入（临时文件 + fsync + rename），写入时持有引擎锁；
  快照完成后重置日志。

**恢复流程**：

1. 加载快照（若存在），还原账户、委托、成交、幂等缓存与序号。
2. 将快照中的活跃委托重建到挂单簿。
3. 回放快照之后的日志事件。回放是确定性的（价格优先撮合 + 整数结算），
   恢复后的状态与最后一次提交时刻完全一致。
4. 日志最后一行若为半写 JSON（进程崩溃导致的 torn write），检测后丢弃并截断日志，
   部分写入不会污染恢复。

**失败处理**：

- 日志追加失败 → 回滚内存变更，不留下部分写入，返回 `persistence_failure`，可重试。
- 校验失败（余额不足、参数错误等）→ 不变更任何状态。
- 快照失败 → 不影响内存状态，系统可继续推进。

## API 概览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/accounts` | 开户（含初始余额） |
| POST | `/api/accounts/{id}/deposit` | 充值（测试/发行） |
| GET | `/api/accounts/{id}` | 查询账户余额与冻结 |
| POST | `/api/orders` | 提交限价委托（支持 `Idempotency-Key` 头） |
| POST | `/api/orders/{id}/cancel` | 撤单 |
| GET | `/api/orders` | 委托列表（支持 account_id/status/limit/cursor） |
| GET | `/api/orders/{id}` | 查询单个委托 |
| GET | `/api/trades` | 最近成交（支持 limit/cursor/start_ts/end_ts） |
| GET | `/api/depth` | 挂单深度（买卖盘口） |

### 分页

- 成交与委托列表均支持**稳定游标分页**：`cursor` 为上一页最后一条的序号，
  返回序号大于 cursor 的记录，按序号升序，配合 `next_cursor` 翻页。
- 支持时间范围过滤：`start_ts` / `end_ts`（Unix 时间戳）。
- 游标基于单调递增的事件序号，翻页期间不受新数据影响，结果稳定。
